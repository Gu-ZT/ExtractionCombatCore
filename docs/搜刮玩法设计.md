# 搜刮玩法与数据包设计

玩家可以提前结束翻找，带走已经找到的物品；是否值得继续开柜、等下一件揭示或整理出一块空间，是本模组留给玩家的三个选择。本文定义计划中的玩法和数据包格式，范围限于搜刮、开启和收纳。文中的时长、颜色与判定窗口是供试玩的初始值。

## 从维修柜带走一件工具

维修间里有一只通电的储物柜。持维修钥匙的玩家长按一秒便可开门；持译码器的玩家也能开门，但要留在柜前等待，或通过节奏判定缩短等待。门开后，玩家先看到柜子的分区和灰色遮罩。放大镜扫过主仓，第一件显露的是一小叠铁粒，玩家可以双击收进背包，也可以继续等下一件。

第二件是横杆宽五格的挂钩。背包正面朝上时某一行只空四格，但右侧有五格高的竖缝。玩家拖起挂钩，靠近目标槽右边缘，预览转为朝右，刚好可以放入。若两个方向都没有整条空隙，双击转移才会尝试重排。玩家也可以拿着铁粒离开，把挂钩留给下一位搜柜的人。

## 玩家库存策略

库存策略由服务端生效，对同一玩家的界面、拾取和物品操作使用同一规则。建议配置如下，两项可以独立修改：

```json
{
  "vanilla_main_inventory_enabled": false,
  "enabled_hotbar_slots": 3
}
```

- `vanilla_main_inventory_enabled` 默认为 `true`，控制原版主背包的 27 格；`enabled_hotbar_slots` 默认为 `9`，取值 `0` 至 `9`，按从左到右开放。护甲、副手和合成栏保持各自原有用途。
- 上例仅开放前三个快捷栏，主背包不再收物。禁用位置不参与拾取、数字键交换、滚轮选择、快捷转移或物品使用。若收紧配置时禁用槽已有物品，界面提供只取不放的取回操作。零快捷栏时主手不从禁用槽取物。
- 拾取优先尝试可用的原版槽，再尝试独立装备位上的随身背包。背包只尝试直接放入，无处可放的数量留在地上。手动双击在当前选用的背包与对侧面板之间转移整叠物品。原版槽沿用原版单槽和堆叠规则，多格占用只在本模组的网格内生效。

## 网格与拖动

`shape` 的每行等宽，行由上到下、列由左到右。仅识别大写 `X` 和半角空格，首尾空格也计入行宽。容器的 `X` 表示可用格，空格是缺口；物品的 `X` 表示占用格，空格不参与碰撞。物品形状 `["  X  ", "XXXXX"]` 是宽五高二的六格物品，上排的四个空位仍可放别的物品。未配置的物品按 `1×1` 处理。

背包的外部形状与内部容量独立。每个内部分区有自己的网格，可用 `accepts_tag` 限制可存物品；即使两个分区在画面上紧挨着，一件物品也不能跨区。保留物品栈的组件、名称和耐久；只有原本就可合并的栈才可合并。每叠占一个形状，数量上限取原版上限与 `grid_stack_limit` 的较小值。背包实例不堆叠，可以放进世界容器，禁止装入另一只背包。丢出、交易或拾起背包时，内容物随同一实例转移。

**拖动时用槽位四边选向，不需要旋转键。** 抓起物品的那一格始终跟随指针。靠近目标格的上、右、下、左边，分别选择相对定义形状的 0°、顺时针 90°、180°、270°。进入距边缘四分之一格宽的范围才切换，中心区域维持当前方向；靠近角落取最近边，等距时保留当前方向。固定朝向物品忽略四边切换。预览逐格标出越界、缺格和碰撞，松手时才放置，失败则回到原位。四边选向仅用于网格拖动，破译小游戏仍可使用空格键。

### 网格图标与原版栏图标

物品定义的 `icons` 可以为同一物品指定两张贴图。物品显示在哪种槽位就选哪张图，即使同一个界面同时打开了背包和原版物品栏，也分别绘制。两项可独立省略，不改变物品栈、手持外观或掉落物外观。

| 字段 | 使用位置 | 绘制方式 |
|---|---|---|
| `icons.grid` | 模组背包与容器的网格 | 按未旋转 `shape` 的完整行宽与行数确定画布，整张贴图只画一次，并裁去空格对应的区域。拖动预览和放置后的贴图都随占格同步转向。 |
| `icons.vanilla_slot` | 原版物品栏的单格，包括快捷栏 | 在一个槽位内保持贴图比例、居中显示，不继承网格中的朝向。转移回模组网格时重新使用网格显示规则。 |

例如挂钩的 `shape` 为 `["  X  ", "XXXXX"]`，可用 `80×32` 的 PNG，每格对应 16 像素；`160×64` 也符合相同的 5:2 比例。旋转 90° 后画布从五格宽、两格高变为两格宽、五格高。上排四个空格即使画有不透明像素也要裁掉，以便另一件小物品在凹口内独立显示和点击。贴图的透明度不参与占格与点击判定，启用品质显示时，边框沿六个 `X` 的轮廓绘制；未揭示时不显示物品图标或边框。

数据包只声明贴图 ID，PNG 由客户端加载的资源包提供。ID `example:item/service_hook_grid` 对应 `assets/example/textures/item/service_hook_grid.png`；单格贴图使用相同的路径规则。未配置 `grid` 时，在物品定义的首个 `X`（从上到下、从左到右，位置随形状转向）只显示一次物品栈原有的单格图标；未配置 `vanilla_slot` 时，原版槽使用该栈原有的显示方式。缺少已配置的资源或网格贴图宽高比不符时，客户端报告对应字段及资源 ID，仅该字段按未配置处理。另一张自定义图标不受影响，库存布局与存档也不变。

### 双击转移与按需整理

双击已揭示的物品，将整叠从当前面板转到对侧面板。背包与容器双向适用；打开多个背包时，界面标明当前参与转移的那一只。目标分区必须接受该物品，向世界容器存入时只使用该玩家已搜完的分区。

1. **先直接放。** 在不移动、不旋转已有物品的前提下，先模拟合堆，再为剩余数量找位置。按定义的分区顺序、当前朝向优先、其余允许朝向顺时针、格点从上到下从左到右检查。整叠能接收就立即提交，其他物品的坐标与朝向保持不变。
2. **直接放不下才整理。** 在副本上把待转物与目标侧可整理的内容一起排布，允许挪动和旋转，仍须遵守分区过滤、禁用槽和堆叠上限。未搜完的分区不参与整理。优先保留原分区与原位；只要找到合法布局即可，不要求最紧凑。面积足够不代表有解。搜索允许分批处理；执行期间显示「正在整理」，取消时不更改布局。
3. **一次结算。** 服务端确认来源和目标仍是同一版库存后，一次应用扣除、合并与新布局。若没有合法排布则提示空间不足。若同伴先改了库存则刷新界面，提示重试。任何失败都不扣来源数量，也不留下部分合堆或半次整理。手动拖放失败不会触发整理。

## 搜索与品质显示

世界容器的 `per_item` 模式默认逐件揭示：首次访问时生成并保存该实例的战利品和位置。搜索按分区定义顺序进行，同区按位置从上到下、从左到右揭示。一叠物品算一件。`ticks_per_item` 控制一次揭示时长；空分区也经一次检查后才显示「空」。工具架等可配置 `instant`，打开就能看清。自己的背包默认直接可见。

- **正在找：** 未知格统一盖上灰色不透明遮罩，运动的放大镜在正在搜索的分区上来回扫动。运动路径与下件物品的位置、大小和品质无关。未知格不能悬停看提示、点击取物或试放。
- **找到了：** 一次揭开整件的所有占用格，显示图标、数量，以及已启用的品质边框，玩家当即可以拖动或双击。凹口内尚未揭示的格仍有遮罩。该分区搜完后才揭开剩余空格，开放存入。关界面、离开范围或受伤会中断当前一次揭示；下次从尚未完成的物品继续。
- **品质：** 在物品实际占格的轮廓上绘制边框，相邻占用格之间不重复描线。读取命中的物品定义：省略 `quality` 时沿用当前栈的原版稀有度，填写品质资源 ID 时使用对应共享定义的名称与边框色，也可内联完整的品质对象供该物品单独使用。`"quality": "disable"` 和 `"quality": { "id": "disable" }` 等价，均隐藏边框和模组添加的品质提示，不再回退到原版品质。禁用只影响显示，保留图标、数量和原有稀有度。例如普通绊线钩默认显示原版普通品质；采用下文定义后显示橙色「精工」。启用品质显示时，悬停提示同时注明品质名称，避免只能靠颜色判断。
- **多人：** 锁状态和库存属于容器，发现记录属于玩家。甲开门后乙可以直接搜，但两人不会共享揭示信息。甲拿走物品，乙已揭示的对应物品立即消失；未揭示的一方不会收到名称或品质。自己放入的物品对自己立即可见。若他人向已搜完的分区存入或重排该区，保留仍可确认的发现；对该玩家尚未知的新物品重新遮盖未知区域，搜索后再开放存入。

## 开启条件与小游戏

每个世界容器可声明 `access.routes`。路线之间任选其一；同一路线的 `requires` 须同时成立，`steps` 按顺序完成。省略开启规则则正常交互即开。路线可要求持有钥匙或工具、红石供电或指定地图机关已解锁；可配置右键、潜行交互、持续按住和下列小游戏。`held_item` 与 `held_item_tag` 各自接受布尔字段 `consume`，默认 `false`，只检查是否持有；设为 `true` 时，成功解锁扣除一件匹配物品。标签条件扣除实际匹配的物品。工具耐久代价与数量消耗分开配置。界面展示路线要求、时长与代价，不展示谜底。

| 步骤类型 | 玩家操作 | 完成与失误 |
|---|---|---|
| `password` | 阅读地图上的线索，在面板输入数字或字符，可用前导零 | 按字符串精确比较；错误清空输入并短暂冷却，允许重试 |
| `audio_morse` | 听短音、长音及字间停顿，按字母或数字输入明文；可以重播 | 译码正确即通过。可显示译码表，并以同步闪灯辅助听辨；重播不更换消息 |
| `pattern_morse` | 观察铭牌上的两种图案及分字间隔，例如圆点表示点、长条表示划；输入明文 | 视觉图案可替换；与音频模式共用点划编码与答案判定 |
| `rolling_lock` | 一排 3～9 位数字或字母，各位纵向滚动。绿底字符进入当前位白框时按空格 | 命中就锁住该位，白框移至右侧下一位；锁定最后一位才完成。误按保留已锁位，暂停所有未锁位，随后从当前位继续 |
| `accelerated_decode` | 下方显示自动增长的进度条，上方光标扫过固定白条，进入白条时按空格 | 默认 400 游戏刻自然完成（正常刻速约 20 秒），每次命中额外增加总进度的 15%。同次经过最多计一次；失误短暂冷却，不扣进度；不按键也会完成 |

例如，一个六位锁可写为：

```json
{ "type": "rolling_lock", "positions": 6, "error_pause_ticks": 40 }
```

`positions` 为 3～9 的整数，默认 5。一次挑战开始时，每位独立确定向上或向下的方向及速度，白框从最左位开始。`error_pause_ticks` 为非负整数，默认 40 游戏刻（正常刻速下为 2 秒）。暂停时忽略按键，不重置计时；到时各未锁位从暂停位置继续滚动，已锁位保持静止。

滚动锁定和加速破译允许重绑按键。服务端维护挑战轮次、计时与成功条件；客户端只接收呈现挑战所需的字符、图案或音符。计时输入按服务端轮次和有上限的延迟容差校验，不凭客户端上报的成功结果开箱。关界面、离开范围、受伤或失去必要条件时中断，本次开锁进度重置。仅在所选路线全部完成时复核条件与锁状态，并在同一次结算中扣费、解锁。小游戏误按、暂停与中断均不扣物；多人同时通过只结算第一位，其他人直接访问已打开的柜子。开锁成功不跳过后续翻找。

## 数据包目录与示例

```text
data/<namespace>/
  extraction/
    backpacks/<backpack>.json
    containers/<container>.json
    items/<item>.json
    qualities/<quality>.json
```

资源类型由目录确定，定义 ID 由命名空间与该目录下的相对路径确定。背包与世界容器分别绑定模组提供的通用背包物品和通用容器方块实例；物品定义通过原版物品谓词 `ItemPredicate` 匹配当前物品栈。共享品质在 `qualities/` 中定义，由物品引用；开启路线写在容器定义中。以下四份定义组成一个示例包；`minecraft` 命名空间的引用指向原版资源。

### `data/example/extraction/backpacks/field_pack.json`

背包实例绑定 `example:field_pack`。`outer` 是背包放入其他网格时的外形，`sections` 是内部空间。主仓有竖向长缝可容纳旋转后的挂钩，侧袋与主仓不连通。

```json
{
  "outer": { "shape": ["XX", "XX", "XX"], "rotatable": true },
  "sections": [
    { "id": "main", "shape": ["XXXX", "XXXX", "XXXX", "XXXX", "XXXX"] },
    { "id": "side", "shape": [" X", "XX"] }
  ]
}
```

### `data/example/extraction/containers/service_cabinet.json`

柜子实例绑定 `example:service_cabinet`。示例用原版绊线钩作钥匙、指南针作译码器，方便测试；地图作者可将 `held_item` 换成 `held_item_tag` 并指定自己的标签。两条路线都需要供电：成功走钥匙路线扣一把钥匙，成功走译码器路线则保留设备。示例借用原版战利品表；验收时可预置铁粒和挂钩以固定测试内容。

```json
{
  "sections": [
    { "id": "main", "shape": ["XXXX  ", "XXXXXX", "XXXXXX"] },
    { "id": "drawer", "shape": ["XXX", "XX "] }
  ],
  "loot_table": "minecraft:chests/simple_dungeon",
  "search": { "mode": "per_item", "ticks_per_item": 24 },
  "access": {
    "routes": [
      {
        "requires": [{ "type": "powered" }, { "type": "held_item", "item": "minecraft:tripwire_hook", "consume": true }],
        "steps": [{ "type": "hold", "ticks": 20 }]
      },
      {
        "requires": [{ "type": "powered" }, { "type": "held_item", "item": "minecraft:compass", "consume": false }],
        "steps": [{ "type": "accelerated_decode", "passive_ticks": 400, "hit_bonus": 0.15 }]
      }
    ]
  }
}
```

### `data/example/extraction/qualities/precision.json`

这份文件定义可复用的橙色「精工」品质：

```json
{ "name": "精工", "border_color": "#F59E42" }
```

从命名空间与 `qualities/` 下的相对路径取得 ID `example:precision`，文件内无需重复写 `id`。任何命名空间的物品定义都可以用 `"quality": "example:precision"` 引用它。如果只给单件物品设定样式，仍可内联，例如 `"quality": { "id": "example:polished", "name": "抛光", "border_color": "#C4CDD6" }`。内联对象不会注册为共享品质，其他物品不能凭该对象的 ID 引用它。保留值 `"disable"` 和 `{ "id": "disable" }` 均直接禁用显示，不查找资源。

### `data/example/extraction/items/service_hook.json`

定义 `example:service_hook` 为绊线钩指定网格占格、网格贴图与原版栏图标，不改变原版注册物品。下例在背包里展示完整挂钩，在快捷栏里展示单格缩略图。移除 `quality` 后，同一件物品恢复使用原版品质边框。

```json
{
  "item": { "items": "minecraft:tripwire_hook" },
  "shape": ["  X  ", "XXXXX"],
  "rotatable": true,
  "grid_stack_limit": 1,
  "icons": {
    "grid": "example:item/service_hook_grid",
    "vanilla_slot": "example:item/service_hook_slot"
  },
  "quality": "example:precision"
}
```

### 多条物品定义同时匹配

`item` 接受原版 `ItemPredicate` 对象。`items` 可指定物品 ID 或 `#` 开头的物品标签；`components` 可对栈上的组件提出额外要求。例如，下面的定义只匹配具有指定自定义模型编号（1.21.8 的 `minecraft:custom_model_data` 组件）的绊线钩，并隐藏这类挂钩的品质：

```json
{
  "item": {
    "items": "minecraft:tripwire_hook",
    "components": { "minecraft:custom_model_data": { "floats": [731.0] } }
  },
  "shape": ["  X  ", "XXXXX"],
  "quality": "disable"
}
```

对同一个栈，先找出所有命中的定义，再排除匹配范围严格包含另一候选范围的宽泛规则。比较物品集合时按当前数据包解析标签，并同时考虑组件等限制。例如，若维修工具标签包含挂钩和其他工具，带指定组件的挂钩优先于任意挂钩，任意挂钩又优先于整个维修工具标签。胜出的定义整条生效，未写的字段使用默认值，不从其他命中定义继承。若剩下多个等价或无法判定包含关系的候选，按完整定义 ID 的字典序取第一条，并报告参与歧义的 ID；文件名只用于平局，不会让宽泛规则覆盖具体规则。

## 加载、存档与异常处理

定义加载时检查全空或不等宽形状、非法字符、重复分区、未知步骤、失效引用、越界数值与品质颜色格式。先按数据包优先级确定每个品质 ID 的有效定义，再解析物品引用，不依赖文件读取顺序。引用缺失时，错误列出物品定义 ID、`quality` 字段与缺失的品质 ID。相同资源 ID 使用数据包优先级覆盖；不同资源 ID 可匹配同一物品栈，按上述具体度与平局规则选择。验证整批通过后才启用，热重载失败沿用上一批有效规则，错误信息定位到资源与字段。

已创建的背包和容器保存布局与规则快照、内容和朝向；世界容器另存解锁状态、生成标记和玩家发现记录。重载时新定义应用于新实例，旧背包不会因缩容而丢物。战利品同一实例只生成一次，放不下的结果保存在待放入列表并提示地图作者；空出兼容位置时再放入，作为未发现物品参与搜索。打开、重连与同时搜索均不得重复生成物品。

## 玩法验收场景

| 场景 | 预期结果 |
|---|---|
| 关闭主背包、开放前三个快捷栏，再将数量调为零 | 拾取与快捷操作只用开放槽；禁用槽内的旧物品能取回，无法继续使用，也不会掉落或消失 |
| 拖动六格挂钩依次靠近四边，再把小件放入其凹口 | 四个方向的预览与抓取格一致；中央不跳向，四个空位可独立占用；跨分区或压到缺格时释放无效 |
| 两侧各放一叠铁粒，双击可合堆物品；再双击可直接旋转放入的挂钩 | 两种情况都不触发重排，目标其他物品的坐标与朝向不变；反向从背包存回已搜完的柜子同样成立 |
| 将目标分区的空格分散放置，只有挪动已有物品才能装下挂钩 | 双击后整件进入目标，仅此时触发整理；若同样面积因分区宽度不足而无解，两侧逐格保持原样 |
| 搜索中途关闭，再打开；另一位玩家同时翻柜 | 已找到的物品保留，灰层不露出下一件的外形或品质；放大镜随搜索启停；同一件只能被一人取走 |
| 给挂钩配置 80×32 网格图和单格图，在背包、容器与快捷栏间来回移动 | 两个模组网格都显示一张完整的 5:2 贴图，转向后变为 2:5；原版栏只显示单格图，凹口里的铁粒始终可见且可单独取走 |
| 分别省略单格图、移除网格图资源、将网格图换成正方形 | 未配置或无效的那一侧按默认规则显示，另一侧仍用指定图；缺图或比例错误提示相应资源 ID，挂钩始终占六格 |
| 同一挂钩依次匹配工具标签、精确物品与限定组件的定义 | 带指定组件时使用整条特例，普通挂钩使用精确物品定义；标签中的其他工具使用标签定义 |
| 分别写 `"quality": "disable"` 与 `"quality": { "id": "disable" }` | 两者都没有边框和模组品质提示；原有稀有度、图标和数量不变 |
| 让两个不同命名空间的物品引用 `example:precision`，再用高优先级数据包覆盖该品质 | 两个物品使用同一份有效定义的名称与边框色，无须逐项修改 |
| 将一个物品引用改为不存在的品质 ID 并重载 | 报告该物品、`quality` 字段与缺失 ID，保留上一批有效定义 |
| 分别使用原版品质和自定义品质的定义搜出挂钩 | 揭示前没有边框或品质提示；揭示后各自采用当前栈的原版边框或自定义橙色轮廓 |
| 分别用密码、音频摩斯、图案摩斯开同一种柜门 | 密码保留前导零；音频重播和同步闪灯表达同一消息；视觉图案按分字间隔可解；错误可重试，中断不扣道具 |
| 分别开 3 位和 9 位滚动锁，在第二位误按并重复按空格 | 第一位保持锁定，其他位暂停 40 刻且不延时，再从第二位继续；改配 20 刻时暂停减半。锁完最后一位才开柜 |
| 使用消耗型钥匙和非消耗型译码器分别开锁，再试一次中断 | 钥匙成功后少一件；译码器成功后数量不变；中断不扣任一道具 |
| 加速破译分别零按键、命中白条、连续误按 | 零按键自然完成，命中比等待更快；同一次白条经过不能反复加成，误按不破坏自然进度 |
| 两人同刻用消耗型钥匙开柜；保存退出后重进并重载更小的布局 | 只扣成功者一次代价；锁状态、物品数量与朝向保留，旧实例不缩水，新实例采用新布局 |
